# nexPDF v1.0.4

## 中文

- 新增打印（文件菜单"打印…"，Ctrl+P）：系统打印对话框支持页码范围（1 至文档页数），逐页按不高于 300 DPI 渲染整页，等比居中打印到可打印区域，状态栏显示进度，完成后显示"已打印 N 页"。UI 不直接接触 PDF 引擎，仍全部经由既有后台渲染会话。
- 验证范围（如实说明）：**打印路径经编译与界面集成验证**——菜单/快捷键/未开文档时禁用等界面集成、打印对话框构造与页码范围在 UI 测试中通过（Linux CI 上含对话框实际弹出的检查），现有核心与界面测试全部通过；**未做实体打印机输出验证**（本机与 CI 均无实体打印机，未做 Windows 原生打印对话框的人工交互检查）。如遇驱动兼容或输出质量问题请提 issue。
- macOS 仍为仅 CI 验证（同 v1.0.2 披露）。

发布包不含代码签名。请核对 GitHub 显示的 SHA-256 摘要。AGPL-3.0-or-later，AI 辅助开发，按原样提供。

## English

- Added printing (File → "Print…", Ctrl+P): the system print dialog offers the page range 1..page-count; pages render whole at up to 300 DPI each, are scaled proportionally and centred onto the printable area, the status bar shows progress and ends with "Printed N page(s)". The UI still never touches the PDF engine directly — everything goes through the existing background render session.
- Verification scope, stated honestly: **the print path is verified by compilation and UI integration** — menu/shortcut/disabled-without-document wiring and the print-dialog construction with its page range are covered by the UI tests (on Linux CI including an actual dialog pop-up check), and all existing core and UI tests pass; **no physical-printer output was verified** (no physical printer locally or in CI, and no interactive manual check of the Windows native print dialog). If you hit driver compatibility or output-quality problems, please open an issue.
- macOS remains CI-verified only, as disclosed in v1.0.2.

Packages are not code-signed. Verify the SHA-256 digest shown by GitHub. AGPL-3.0-or-later, AI-assisted development, provided as-is.
